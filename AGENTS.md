# aulo — instructions for agents

**What this is.** A local-first voice agent that controls the computer: speech in and out with switchable engines, shell/app/browser/desktop control, MCP client and server, plugins, local and remote models. One daemon (`aulod`) serves a gRPC API to the official Compose Multiplatform chat client (`aulo-chat`, D12), the CLI and remote clients.

The implementation stack is **Kotlin/Native** (Gradle KMP, native targets). The project has
been reset: every task in `plan/` is open.

If an `AGENTS.md` or `CLAUDE.md` exists higher in the tree, follow it too; on conflict, ask the creator.

## Read first

- `spec.md` — the specification. Section numbers are stable; tasks cite them.
- `research.md` — sources for every external fact and the reuse map of the workspace (Part 6).
- `plan/` — one folder per task (`plan/<id>/task.md`, closed ones also `done.md`); `plan/README.md` says how to read it. Settled decisions D1–D12 are recorded in `spec.md` §17. Never decide an open question in `spec.md` §17 yourself; ask the creator.

## Hard rules

- **Policy runs outside the model.** Every tool call — built-in, MCP, plugin or a call made through aulo's own MCP server — passes `aulo-policy`. No tool runs before policy returns Allow. Policy fails closed.
- **Voice never widens access.** Destructive, payment and credential actions need a click or key, never only a spoken yes.
- **Secrets never reach the model.** Tools take secret handles; values never appear in prompts, transcripts or logs.
- **Everything from a model, a tool, a web page, a screenshot, an MCP server, a plugin or a remote client is untrusted input.** Wrap it, sanitize it, cap it, and test the cap.
- **Fail open on extensions.** A broken STT/TTS engine, MCP server, plugin, skill or hook is warned about and skipped; voice falls back to the next engine.
- **No unbounded buffers on the audio path.** Audio callbacks never block or allocate; ring buffers are fixed size and overflow is counted.
- **Reuse before writing.** Provider stack, permissions, sandbox, MCP host, speech capture, config helpers and the agent loop come from the shared Kotlin modules planned in S1. Do not copy code from the coding agent, the local model runner or the token-reduction CLI into aulo.
- **gRPC is the API.** Protos in `proto/aulo/v1`; `buf lint` and `buf breaking` must pass.
- **Licences.** Check the licence of every engine and model before wiring it. GPL code (for example Piper) only runs as a separate plugin process. The one exception is espeak-ng, linked by sherpa-onnx (spec §17 D9).

## Layout

- Gradle KMP modules (`aulo-<role>`), created by S2+ tasks, hold the Kotlin/Native daemon and CLI. Every module applies the `aulo.kmp` convention plugin from `build-logic/` (targets per spec §17 D3, warnings as errors, ktlint). `:aulo` is the surface module that links the `aulo` and `aulod` executables.
- Shared Kotlin/Native libraries come from `pyrlyn-kit` in the workspace's `packages/` (pyrlyn/packages), included as a Gradle build: `pyrlyn.kit:<module>` (TOML, files, SQLite, processes, HTTP). Gradle finds it in the first ancestor `packages/` or through `KOTLIN_KIT_DIR` and `SHARED_SETTINGS_DIR`; CI checks it out at a pinned commit. Check it before writing a helper.
- `:aulo-config` is the only module that reads or writes aulo's TOML config. `schemas/aulo.schema.json` is generated from its types; after changing them run `just schema` (the stale-schema test fails otherwise).
- Logs go through `:aulo-telemetry`'s `Logger`, which masks every record with `Redact` before writing. Anything else that shows configured or untrusted text to a person masks it with `Redact` too; do not add a second rule set.
- `:aulo-store` owns SQLite (`aulo.db`). Callers use `Store`'s typed methods; SQL lives only in its `.sq` files (SQLDelight) and in `aulo-store/migrations/<key>/{up,down}.sql`. A schema change is a new migration directory (key `YYYY-MM-DD-HHMMSS_name`) plus the same change in the `.sq` files; `MigrationsTest` fails if the two disagree. Never edit a migration that has reached `main`.
- `aulo` commands are tested in-process from fixtures in `aulo/tests/cmd` (see its README); after an intended output change run `AULO_UPDATE_FIXTURES=1 ./gradlew :aulo:allTests` and review the diff.
- Every module declares its role in its build file, `aulo { role = ModuleRole.X }`: `CONTRACT` (types only: no I/O, HTTP, storage or native library; depends only on contracts), `LIBRARY`, or `SURFACE` (links an executable; the only place for the CLI libraries; nothing depends on it). SQLite, the gRPC stack, sherpa-onnx and a WASM runtime each have one owner module. `./gradlew test` runs `checkModuleGraph`, which enforces this (T2.2); the library lists live in `build-logic/src/main/kotlin/aulo/buildlogic/ModuleGraph.kt` — extend them when a task wires a new library of one of those kinds.
- `aulo-chat/` — the official Compose Multiplatform chat client (D12, T12.22), which replaces the native apps of D2, and its development server; its own Gradle build, commands in `aulo-chat/README.md`, screens described in `aulo-chat/design/`. UI and logic live in shared Kotlin/Compose source sets; Android, iOS and desktop keep only the minimum host Compose Multiplatform requires.
- `proto/aulo/v1/` — gRPC service definitions (T3.1).
- `:aulo-proto` is that API as Kotlin: Wire generates the messages and one `<Service>Server` interface per service into `build/generated` on every build (spec §17 D10). Nothing generated is committed; change the `.proto` files, never the output. It holds no transport.
- `:aulo-grpc` owns the gRPC stack: gRPC over HTTP/2 on nghttp2 for every target (spec §17 D11). It knows no aulo service.
- TLS (T3.8) is mbedTLS 3.6 behind the C shim `aulo-grpc/src/nativeInterop/cinterop/mbedtls.def`: TLS 1.3 only, ALPN `h2`, a memory BIO (Kotlin moves the socket bytes, `TlsStream`). mbedTLS is built without threading, so every shim entry point takes one process-wide lock; keep new entry points under it. Clients pin the SHA-256 of the server certificate's DER (`TlsClient`); there is no CA verification. In aulod (`ServerTls.kt`) `daemon.listen` always serves TLS: the configured `tls_cert` and `tls_key`, or a self-signed certificate made once in `<home>/tls` (through `FileSecretStore`) whose pin aulod logs at start. `aulo connect ADDR --pin SHA256` checks a remote aulod with that pin and the token in `AULO_TOKEN`, and saves nothing.
- `:aulo-speech` is the speech engine contract (T7.1): `SttEngine`, `TtsEngine`, `Vad`, `KeywordSpotter` and `TurnDetector`, all push then poll, never suspending and never blocking, with output written into caller buffers. Every engine throws only `SpeechException`; its `shouldFallBack` is what lets the registry skip a broken engine. Engine ids, names, voices, language tags, error details and transcripts are untrusted and capped where the types are built; keep new engine-facing types the same.
- `:aulo-voice` picks the engine (T7.2): `SttRegistry` and `TtsRegistry` hold engine factories by id, `candidates` resolves chat over bot over `[voice.stt]`/`[voice.tts]` into an ordered list, and `ActiveStt`/`ActiveTts` build lazily, fall back past failing engines with a WARN notice each, and apply `switch` at the next begin. An engine or factory that throws anything but `SpeechException` is treated as an engine fault. `EngineConfig.choice` in `:aulo-config` turns a raw section into an `EngineChoice`. Its `aulo.voice.speak` package is the text side (T7.15): `speakable` turns a markdown reply into what TTS says (code and tables become "It's on the screen.", URLs their host, `%` and units words with Russian plurals; input capped at 64 KiB, speech at 2000 characters), and `SpeakableStream` and `SentenceSplitter` cut it into sentences as deltas arrive. Markdown is parsed by `org.jetbrains:markdown` after `limitNesting` caps quote and list nesting, because its parse time grows with the square of the depth. Golden outputs live in `aulo-voice/tests/snapshots`; after an intended change run `AULO_UPDATE_FIXTURES=1 ./gradlew :aulo-voice:allTests` and review the diff. Write invisible characters (bidi, zero-width) as code points, never as `\u` escapes: ktlint rewrites escapes into the characters themselves.
- `:aulo-testkit` holds the fake engines tests share; only test source sets depend on it.
- `:aulo-server` binds services to it. Kotlin/Native cannot reflect, so `GrpcTables` in `build-logic` (a Wire schema handler) writes `grpcHandlers()` for every `<Service>Server` interface and the file descriptors that server reflection serves; pass `service.grpcHandlers()` to `AuloServer`. Health and reflection are built in. `grpc.health.v1` and `grpc.reflection.v1` are vendored in `aulo-server/src/proto/`; never edit them. With `AULO_GRPCURL` naming a grpcurl binary, the server tests also check the server with grpcurl.
- Authentication (T3.4): `AuloServer` runs every method, built-ins included, through `Authenticator`. The local socket is `<aulo home>/run/aulod.sock`; `run/` is made 0700 before the bind and the socket 0600 after it, so the socket's owner is the only client and needs no token. A TCP call needs `authorization: Bearer <token>`; only SHA-256 hashes of tokens are stored (`api_tokens` in `:aulo-store`), compared in constant time. `ensureFirstToken` makes the first token (scope `admin`) and puts its value in the secret store.
- Services share the daemon's one `Store` through `SharedStore` (one caller at a time, off the transport threads). Lists page as `common.proto` says, with opaque `page_token`s that hold aulo-store's keyset cursors (`Pages.kt`); reuse them for every list RPC. `ChatService` (T3.5) is the first service.
- `aulod run` (T3.6) is `runDaemon` in aulo-server: one aulod per home through a `FileLock` on `run/aulod.lock`, a pidfile beside it, `serviceHandlers` for the services it serves (add new services there). `--config FILE` replaces `<home>/config.toml`; the home comes from `--home`, else `AULO_HOME`, else the user directory. On Unix SIGINT and SIGTERM reach it through a self-pipe in `aulo/src/nativeInterop/cinterop/signals.def`, because the Kotlin/Native runtime starts threads before `main` and signal masks cannot cover them; do not replace it with `sigwait` or a Kotlin handler.
- `aulod service install|uninstall|status` (T3.9) lives in `aulo/app/service`: launchd, systemd --user and Task Scheduler backends that touch the machine only through `ServiceManager`, so `FakeServiceManager` tests all three on any host. The service runs `<aulod> run --home <home>` with no environment of its own. Keep new service-manager behaviour in the fake too, and never run a real install in tests.
- `:aulo-secrets` keeps secrets out of files where the OS has a keychain: the macOS Keychain, Windows Credential Manager, or the Secret Service on Linux. libsecret is LGPL, so it is opened with `dlopen` at run time and never linked (the creator's decision in T3.4); without it, or when the keychain fails, `systemSecretStore` warns and falls back to 0600 files in an owner-only directory. Its tests touch the real keychain only with `AULO_KEYCHAIN_TEST` set.
- `:aulo-models` (T7.3) installs speech models into `<aulo home>/models/<id>` from the catalog in `aulo-models/data/models.json`, which is embedded in the binary. Every entry is pinned to an immutable URL (a Hugging Face commit) with each file's size and SHA-256; a new model needs its licence checked and its pins written into `research.md`. A download streams into `<file>.part`, is hashed on the way and reaches its final name only when the hash matches; a dropped connection keeps the partial and the next pull resumes it with `Range`. One pull or removal per model at a time through a `FileLock` on `models/<id>.lock`. The HTTP client comes from the caller (`aulo` passes `KtorHttp(MODEL_HTTP_SETTINGS)`), so tests use an in-process fake. `aulo models ls|pull|rm` is the CLI.
- Speech engines that run native inference live in helper processes, so a crash there is an engine failure and aulod survives (T7.4). `:aulo-speech-helper` is the pipe protocol (`Wire.kt`: a type byte, a u32 LE sequence number and a u32 LE length, every payload capped before it is read), `HelperStt`, the `SttEngine` aulod drives over a `HelperLink`, `serveStt`, the helper's side, and `ProcessLink`, which runs a helper over pyrlyn-kit's `spawnPipes`; `registerSherpa` adds the `sherpa-parakeet` and `sherpa-moonshine` engines to an `SttRegistry`, each built only when its catalog model is installed. `:aulo-speech-sherpa` is the `aulo-speech-sherpa stt <parakeet|moonshine> <model dir> <threads>` executable, the one module that links sherpa-onnx. Helpers write only frames to stdout and never put transcripts on stderr. `WerTest` there checks word error rate on FLEURS dev when `AULO_SHERPA_MODELS` and `AULO_FLEURS` are set; run it after touching the recognizer or the model pins. `HelperProcessTest` drives the helper Gradle links for the test task (`AULO_SHERPA_HELPER`); its full-utterance case needs the same two variables.
- `:aulo-speech-openai` (T7.6) is an `SttEngine` over an OpenAI-compatible `/audio/transcriptions` endpoint: OpenAI, a local server or any compatible one, each an `OpenAiEndpoint` with its own engine id, registered with `registerOpenAi`. The utterance is kept as 16-bit samples up to `maxAudio` and posted as one WAV on `finish`; the answer is read through kit-http's `streamPost` and capped while it is read, as JSON or as server-sent events whose deltas become partials. The API key is a `SecretStore` name read per request into the header only; a base URL takes no credentials or query, and a key goes over plain HTTP only to this machine. Tests use the in-process `FakeTranscriber`.
- C libraries come only through Conan. A module applies the `aulo.conan` plugin, lists them in its `conanfile.txt`, pins their recipe revisions in its `conan.lock`, and binds each one with `conan { cinterop(...) }` and a `.def` file. The profiles in `conan/` take Conan Center's binaries on macOS and build Linux and Windows from source with Kotlin/Native's own clang and sysroots. After changing a `conanfile.txt`, recreate its lock: `conan lock create <module>/conanfile.txt --lockfile-out=<module>/conan.lock -pr:h=conan/macosArm64.profile -pr:b=conan/build.profile`. A package whose requirements differ per platform makes the Linux or Windows install fail on the lock; then extend the lock with those profiles too. A package missing from Conan Center has a recipe in `conan/recipes/<name>/` (the directory name is the package name); `aulo.conan` exports those recipes before every install; on macOS, where everything else is a Conan Center binary, they are the only packages it builds. Any edit to such a recipe changes its revision, so recreate the locks that pin it, deleting each old `conan.lock` first: `conan lock create` reads an existing lock next to the `conanfile.txt`.
- `plugins/` — plugin SDK examples (T11.5).
- `docs/` — guides, threat model, spike reports (`docs/spikes/`). Historical spike reports may describe the retired Rust workspace; new work follows this file and `spec.md`.
- `scripts/sync-issues.py` — creates GitHub issues from the active tasks in `plan/` (dry run by default).

## Commands

jactionlint and hk are pinned in `mise.toml`. `.github/jactionlint.yaml` applies the default profile and the
baseline `.github/jactionlint-baseline.json`. `hk.pkl` runs jactionlint as a pre-push hook:

```bash
mise install                               # JDK 21 and the lint tools
mise x -- ./gradlew test                   # host-target tests (just test)
mise x -- ./gradlew ktlintCheck            # style (just lint)
mise x -- jactionlint                      # lint workflows, composite actions, dependabot.yml
mise x -- jactionlint --baseline-write     # refresh the baseline after fixing findings
mise x -- hk install --mise                # install the pre-push hook once per clone
just api-docs                              # regenerate docs/api from proto/
```
